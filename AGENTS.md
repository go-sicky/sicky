# Go-Sicky Framework: Agent Development Guide

Welcome, Agent. This document provides a comprehensive overview of the **Go-Sicky** framework to assist you in understanding its architecture, conventions, and development patterns.

## 1. Project Overview
**Go-Sicky** is a highly modular and extensible Go framework designed for building robust microservices and networked applications. It provides high-level abstractions for common infrastructure, communication protocols, and service management, allowing developers to focus on business logic.

- **Primary Goal**: To provide a unified, pluggable architecture for microservices.
- **Key Features**:
  - Support for multiple protocols: HTTP dual-stack — Fiber (`server/fiber`) and net/http via `uptrace/bunrouter` (`server/http`) — plus gRPC, TCP, UDP, WebSocket (6 server implementations total).
  - Pluggable Infrastructure: SQL (Bun — PostgreSQL, MySQL, SQLite, MSSQL, DaMeng via `oracledialect`), NoSQL (Mongo), Cache (Redis, Ristretto), KV Store (Badger), Search (Elasticsearch), Analytics (Clickhouse), Messaging (NATS/MQTT infra), Storage (S3). Flat layout `infra/*.go` (10 files, no sub-packages, no shared interface).
  - Messaging & Brokers: NATS, JetStream, NSQ.
  - Service Discovery: Consul, Redis, Local (file-based JSON at `registry/local` — not in-memory). mDNS (`registry/mdns/`) is **deprecated**: 100% commented out, comments kept deliberately, no longer supported and no `zeroconf` dependency will be added.
  - Background Jobs: Cron and Ticker-based job scheduling.
  - Concurrent Task Runner: Goroutine-pool-based task dispatch (`runner/static`).
  - Observability: Prometheus metrics (RED + infra, see §3.6), OpenTelemetry tracing (OTLP/gRPC, OTLP/HTTP, Stdout, Uptrace + B3 propagator), built-in structured logger.
  - CLI Scaffolding: `sicky new/generate/serve/version` via `cli/` + `cmd/sicky` (MCP server stdio/http, project scaffolding for standard/mcp/interactive).

## 2. Core Architecture
The framework is organized into several key layers:

### 2.1 Orchestration (`sicky` — root package)
The root `sicky` package (`sicky.go`, `options.go`, `config.go`, `manager.go` all at repository root, `package sicky`) is the central nervous system. It handles:
- **Initialization**: Command-line flag parsing (`pflag`) and configuration loading (`viper`). Flags: `--config/-C` default `config`, `--config-type` default `json`, `--version/-V` prints `AppName Version (Branch) Build Commit BuildTime` and returns `ErrVersionShown` (the caller exits 0; the library never calls `os.Exit`). Additional `FlagSwitch` bool flags via `Init(opts, switches...)`, which now returns `error` (`ErrAlreadyInitialized` on second call — flag registration is not idempotent, guarded by mutex).
- **Configuration**: Support for local files (JSON etc.) and remote providers (e.g., Consul via `url.Parse(configLoc)` + `AddRemoteProvider`). Config files searched at `/etc`, `/etc/<app_name>`, `$HOME/.<app_name>` (via `os.UserHomeDir`, no longer a literal `$HOME` string), and the current directory. Env: `SICKY_` prefix + dot-to-underscore.
- **Lifecycle Management**: Orchestrating the start and stop of all registered services, servers, brokers, registries, tracers, and infrastructure. Actual `Run()` order: `beforeStart → infra → tracer → registry (InitPool first, then pool purge ticker with done-channel) → broker → flag callbacks → manager → services.Start + registry.Register → afterStart → signal wait (TERM/INT/QUIT/ABRT shutdown, HUP triggers OnReload callbacks, or Context cancel) → beforeStop → services.Stop+Deregister (failed service skipped, no double-stop) → broker.Disconnect → registry.Stop → tracer.Stop → manager.Stop → infra shutdown (errors collected via errors.Join) → afterStop`. All startup failures return a joined `error` and run the full shutdown sequence — no `os.Exit` inside the library.
- **Manager**: A built-in HTTP server (`manager.go NewManager`, nil-config safe) that exposes 8 endpoints: `/metrics` (public, for Prometheus scraping), `/health` + `/ready` (same component aggregation: only `unhealthy` degrades overall status; `not_configured` is reported but healthy; infra probes run concurrently under a 2s ctx and recover panics (a probe panic degrades that component, not the process), business checks run one at a time through `runCheck` (own 2s deadline, panic-safe, immune to a checker that ignores its context), Bun via `PingContext`; component error text is redacted to `"unhealthy"`, detail goes to server logs), `/live` (static 200, no probes), `/version`, `/info`, `/config` (403 if `ExposeConfig==false`, secrets redacted when exposed), `/services` (pool snapshot). Business checks join via `RegisterHealthChecker` (merged into `/health`+`/ready`). `/config` + `/services` require `Authorization: Bearer <auth_token>` when `ManagerConfig.AuthToken` is set, else loopback-only **and** Host-allowlisted (loopback name / listen address / `allowed_hosts` - defeats DNS rebinding, which lands on loopback). Failed tokens are throttled (`authThrottle`: 10 per minute, then 429; constant-time digest compare, no length oracle). Optional `tls_cert_pem`/`tls_key_pem` serve HTTPS (TLS 1.2+, half-config fail-fast); empty stays plaintext. `http.Server` carries `Read/Write/IdleTimeout` (defaults 10/10/60s); default bind is `127.0.0.1:8888` (loopback) — an external bind must be configured explicitly.

### 2.2 Infrastructure (`infra`)
Manages connections to external systems. Flat package `infra` with 10 files (`badger.go`, `bun.go`, `clickhouse.go`, `elastic.go`, `mongo.go`, `mqtt.go`, `nats.go`, `redis.go`, `ristretto.go`, `s3.go`), each with `*Config` struct + package-level global singleton + `Init*(*Config)` function. Unlike other subsystems, `infra` does not define a shared Go interface — each component is a standalone module with its own concrete type. Globals: `Badger *badger.DB`, `Bun *bun.DB`, `Clickhouse *ch.DB`, `Elastic *elasticsearch.Client`, `Mongo *mongo.Client`, `MQTT mqtt.Client`, `Nats *nats.Conn`, `Redis *redis.Client`, `Ristretto *ristretto.Cache[string,any]`, `S3 *s3.Client`.

### 2.3 Abstractions & Interfaces
Go-Sicky heavily relies on Go interfaces to maintain decoupling:
- **`service.Service`**: Represents a logical unit of business functionality. Manages subordinate servers, brokers, jobs, registries, and tracers. Implementations: `Standard` (background microservice), `Interactive` (CLI), `Mcp` (+ `mcp/protocol`).
- **`server.Server`**: Handles incoming requests on a specific protocol (Fiber HTTP, net/http via bunrouter, gRPC, TCP, UDP, WebSocket — 6 implementations).
- **`broker.Broker`**: Manages asynchronous message publishing and subscription (NATS, JetStream, NSQ).
- **`registry.Registry`**: Handles service registration and discovery (Consul, Redis, Local file-based JSON).
- **`tracer.Tracer`**: Manages OpenTelemetry spans (OTLP/gRPC, OTLP/HTTP, Stdout, Uptrace). Fiber propagation lives in `server/fiber/propagation.go` (W3C+B3 extract, request-id generation).
- **`job.Job`**: Represents a background job (Cron via `gocron/v2`, Ticker).
- **`runner.Runner`**: Consumes and dispatches concurrent tasks (static goroutine pool at `runner/static`).
- **`client.Client`**: Outbound service client for various protocols (HTTP, gRPC, TCP, UDP, WebSocket).

### 2.4 Registration Pattern
Each abstraction layer uses a self-registration pattern via global state:
- The `New()` constructor of each implementation calls the package-level `Set(self)` function, adding itself to a global map (e.g. `broker.Set(brk)` in `broker/nats`, `tracer.Set(tc)` in `tracer/{grpc,http,stdout,uptrace}`, `server.Set(srv)` in `server/grpc`, `registry.Set(rg)` in `registry/{consul,redis,local}`). Citations here name symbols, not `file:line`: line numbers rot on every edit, and this document previously carried four that were already wrong.
- The first registered instance becomes the "default" singleton, accessible via `package.Default()` (all eight abstractions: `broker`, `registry`, `server`, `tracer`, `service`, `client`, `job`, `runner`). First-registration-wins, so the default is whichever implementation's `New()` ran first — in `Run()` that is config order, not an explicit choice.
- The orchestrator (`sicky.go`) creates instances via `New()` based on configuration presence, which triggers self-registration.
- **Exceptions**:
  - In `sicky.go` the orchestrator uses concrete types (e.g. `*rgConsul.Consul`, `*rgRedis.Redis`, `*brkNats.Nats`) for implementation-specific methods like `Watch()`. This is an acknowledged exception to the "always use abstractions" rule, necessary when specific implementations expose methods not present in the interface.

## 3. Development Conventions

### 3.1 Component Pattern
Most components follow this structure (interface lives in `{package}.go`, not `interface.go`):
- `{package}.go` (e.g. `broker/broker.go:40`, `server/server.go:42`, `registry/registry.go:40`): Defines the core interface (`Broker`, `Server`, `Registry`, etc.).
- `options.go`: Defines the `Options` struct — runtime parameters (name, ID, logger, context, lifecycle hooks). Uses `Ensure()` to provide defaults.
- `config.go`: Defines the `Config` struct — Viper-serializable configuration (JSON/YAML/env). Uses `Ensure()` to provide defaults.
- `Ensure()`: A method on both `Options` and `Config` that fills in sensible default values for zero-valued or nil fields. Always returns the receiver (or a new instance if nil).

**Distinction**: `Options` carries runtime state and references (context, logger, hooks). `Config` carries serializable settings (addresses, timeouts, flags). Both must have `Ensure()`.

**Empty top-level `Config`s**: `server` (`server/config.go:33`), `client` (`client/config.go:33`), `tracer` (`tracer/config.go:33`), `job` (`job/config.go:33`), `broker` (`broker/config.go:33`), `runner` (`runner/config.go:33`), `runner/static` (`runner/static/config.go:33`) are all fieldless (`type Config struct{}`) but **all now have nil-safe `Ensure()`** — they are placeholders for future fields, not a gap. Same for all 10 `infra/*Config` types, which additionally have `Validate()` (§3.5).

**Options duplicate**: `options.go:64` and `options.go:84` both check `if o.Context == nil { o.Context = context.Background() }` — harmless duplication.

### 3.2 Configuration
- **Viper** is used for all configuration.
- Environment variables are automatically mapped using the `SICKY_` prefix (e.g., `SICKY_APP_NAME` from `options.go` `DefaultEnvPrefix`), with dot-to-underscore replacement (`sicky.go` `SetEnvPrefix`+`SetEnvKeyReplacer`+`AutomaticEnv()`).
- **Env vars only resolve keys viper already knows** (`Unmarshal` walks `AllKeys()` = override + flags + *explicitly bound* env vars + config file + defaults — the automatic env namespace is not in there). A `SICKY_*` variable whose key is absent from the config file is therefore dropped: `env.go` `bindSensitiveEnv` calls `BindEnv` for the security-critical keys (`sensitiveEnvKeys`: manager auth/TLS, tracer DSN/headers, infra credentials, `log_level`, ...) so those always work, and `warnIgnoredEnv` logs every other `SICKY_*` variable that resolves to no known key ("will be ignored") instead of dropping it silently. Add new secret-ish keys to `sensitiveEnvKeys` when they appear in `Config`.
- Config files are searched at `/etc`, `/etc/<app_name>`, `$HOME/.<app_name>`, and the current directory (`sicky.go:139-143`, `configLoc` default `config` at `sicky.go:82`, `configType` default `json` at `sicky.go:83`).
- No `context.TODO()` exists in the codebase (`grep` 0 hits) — use `context.Background()` for static initialization (`options.go:65`, `sicky.go:239`, `manager.go:78`, `broker/options.go:66` etc.) or pass a derived context for operations with timeouts.
- Viper's `AutomaticEnv()` performs type coercion for environment variables. Non-numeric values for `int` fields silently become zero. `validateConfig()` in `sicky.go` runs after `Ensure()` and **clamps** invalid values back to defaults with a Warn (never aborts): `Tracer.Timeout<0 → 0`, `SampleRate` outside `[0,1] → 1.0`, `Manager.Shutdown/Read/Write/IdleTimeout<=0 → defaults`, unknown `LogLevel` warns (behaves as info). Infra timing fields (e.g. `Ristretto.NumCounters`) are still not validated and will silently zero-out with a bad env var.

### 3.3 Lifecycle Hooks

The framework provides hooks at two levels:

**Sicky-level** (register via `sicky.BeforeStart()`, etc.):
- `BeforeStart`, `AfterStart` — executed before/after all services start.
- `BeforeStop`, `AfterStop` — executed before/after the full shutdown sequence (service stop, broker disconnect, registry stop, tracer stop, manager stop, infra shutdown).
- `OnReload` — executed on `SIGHUP` in a dedicated goroutine while the process keeps serving (register via `sicky.OnReload()`). `SIGHUP` no longer triggers shutdown.
- Wrapper signature: `SickyWrapper func(context.Context) error`.
- Hook failures log an error but do NOT abort the process (they use `ErrorContext`, not `Fatal`).

**Server-level** (set via `server.Options.BeforeStart()` etc. at `server/options.go:98`):
- `BeforeStart`, `AfterStart` — executed within each server's `Start()` method.
- `BeforeStop`, `AfterStop` — executed within each server's `Stop()` method.
- Wrapper signature: `ServerWrapper func() error` (`server/options.go:41` — no `context.Context` unlike `SickyWrapper`).
- Registration via `server.Options` setter methods: `opts.BeforeStart(w ...ServerWrapper)`. Invocation via `opts.RunBeforeStart()` etc. inside each server implementation (`server/grpc/grpc.go:211,317,331,344` etc.). Runners log failures via `ErrorContext` (`server/options.go:136`).

### 3.4 Error Handling
- Errors during service start/stop are aggregated using `errors.Join`. The orchestrator collects all errors and continues through the full shutdown sequence (via `goto shutdown` + `runErr` variable) even when individual services fail.
- Constructors (e.g., `New()`) for registry/tracer/broker implementations may return `nil` on initialization failure (`tracer/grpc/grpc.go:89,140`, `registry/consul/consul.go:76` etc.). Callers in `sicky.go` must check for nil before calling methods on the returned value. Tracer `nil` is logged as Warn (tracing silently disabled otherwise).
- `logger.Fatal()` calls `os.Exit(-1)` (`logger/logger.go:194`) and must NOT be used in the orchestrator or request paths — `sicky.go` no longer calls it (all startup failures return errors and run shutdown). Remaining `Fatal` calls in `server/*` constructors are tolerated for startup but avoid in request paths.
- All sentinel errors are defined as exported package-level variables (e.g., `broker/nats.ErrBrokerNotConnected`, `sicky.ErrVersionShown`, `sicky.ErrAlreadyInitialized`) to enable `errors.Is()` checks by callers.
- `broker.Message.Format()` and `Scan()` return errors for marshalling/unmarshalling failures — callers must check them. The contract that makes checking mandatory: **a failed `Format` leaves the message exactly as it was** (same `Body`, same `Mime`), because it encodes into a local and commits only on success. Do not assign a codec's result straight into `m.Body` — both `json.Marshal` and `msgpack.Marshal` return nil bytes alongside the error, which is how an earlier version wiped the payload and left `Mime` naming a codec that no longer described it (published empty, scanned clean on the far side). `Scan` on a `MsgRaw` message is a documented passthrough: it returns nil and does not decode.

### 3.5 Infra Conventions
- Each infra singleton is guarded by the package `mu sync.RWMutex` (`infra/infra.go`). Writers are `Init*` (first-wins) and `Clear*` (shutdown, resets to nil so a later `Run()` rebuilds fresh). **Readers must use the `Get*()` helpers** — reading the exported globals directly races with Init/Clear. When adding infra init functions, keep the first-wins duplicate handling (close the just-opened duplicate, return the existing singleton) instead of leaking it.
- Each infra type must have a **nil guard** before overwriting the global variable: `if Xxx == nil { Xxx = client }`. This prevents connection leaks on repeated `Init*()` calls. All 10 comply (`infra/badger.go:64`, `infra/bun.go:137`, `infra/clickhouse.go:73`, `infra/elastic.go:62`, `infra/mongo.go:86`, `infra/mqtt.go:65`, `infra/nats.go:56`, `infra/redis.go:74`, `infra/ristretto.go:74`, `infra/s3.go:57`).
- Infra `Init*()` functions are expected to emit Info logs on success and Error logs on failure, using `logger.Logger`. All 10 comply; credentials (DSN/URI userinfo, passwords, tokens, API keys) must never appear in log fields — use `redactDSN()` for DSN/URI and log only endpoint/username for the rest.
- Infra Config structs all implement `Ensure()` (defaults) + `Validate()` (presence-means-enabled abort on missing required fields; timing fields use zero-fills-default / negative-aborts) — no gap remains.
- The infra shutdown sequence in `sicky.go` follows a specific order: Ristretto → Badger → Elastic → Nats → Redis → Bun → Clickhouse → S3 (log-only, `s3.Client` has no `Close()`) → Mongo (`Disconnect` with 5s timeout ctx) → MQTT (`Disconnect(250)` grace). Close/Disconnect errors are collected via `errors.Join` into the `Run()` return value, never aborting the sequence. Init order differs (Badger→Bun→Clickhouse→Elastic→MQTT→Mongo→Nats→Redis→Ristretto→S3) — not required to mirror shutdown.

### 3.6 Metrics Conventions
- Prometheus metrics are defined in `metrics/metrics.go` as `sicky_`-prefixed `CounterVec`/`HistogramVec`/`GaugeVec` (server RED, client RED, broker, job, runner, registry, infra, manager) plus 3 collectors (`build_info`, `go_collector`, `process_collector`), all exported as package-level variables. The old unlabelled `num_*` counters were removed (breaking change).
- Each collector is registered in the `init()` function via `metrics.Register()`; helpers `ObserveServerRequest`/`ObserveClientRequest`/`ObserveBrokerPublish`/`ObserveBrokerHandler`/`ObserveJobRun`/`ObserveRegistryOp`/`ObserveInfraOp` (+ `CountInfraInit`/`SetInfraUp`) keep call sites to one line.
- The Manager's `/metrics` endpoint serves all registered collectors via a single `prometheus.Registry` created once during `NewManager()` (`manager.go:83-85` `prometheus.NewRegistry()` + `MustRegister(slices.Collect(maps.Values(metrics.GetAll())))`, served via `promhttp.HandlerFor` at `manager.go:196`).
- Server observations happen in the access-log interceptor/middleware after the handler returns (status/code known): gRPC `server/grpc/logger.go`, Fiber `server/fiber/logger.go`, HTTP `server/http/logger.go`; TCP/UDP/WebSocket observe around the `OnData` handler loop (`server/tcp/tcp.go`, `server/udp/udp.go`, `server/websocket/websocket.go`) with rejections counted separately in `sicky_server_rejected_total{server,reason}`.
- **Error responses**: a failing handler must produce a real response - bunrouter's `ServeHTTP` discards the returned error (`_ = r.ServeHTTPError(...)`) and fiber's `DefaultErrorHandler` echoes `err.Error()` to the client. `server/http` ends its chain with `NewErrorMiddleware` (innermost: panic → generic 500 + stack in the server log; error → status/body only when nothing was written yet) and `NewStatusMiddleware` now runs **first** so every layer - recovery included - writes through the recorder; `server/fiber` sets `fiber.Config.ErrorHandler` plus an innermost `recover` copy (`NewErrorHandler`/`NewPanicHandler` in `server/fiber/errors.go`), and its access logger derives the status from the error via `mapFiberError` because fiber applies the error handler *after* the chain has returned. Client-facing text comes from `bunrouter.HTTPError` / `*fiber.Error` / `*utils.CodedError` only; everything else answers `internal server error` (never `err.Error()`), and panics increment `sicky_server_panics_total`.
  - **Client metrics**: real RPCs only — gRPC `Invoke` (unary, method+code+duration) and stream opens, HTTP `Do` (method+host+code+duration). The `Call()` placeholders only bump `{method="noop"}` so they never pollute SLIs. TCP/UDP/WebSocket clients have no real transport yet.
  - **Broker metrics**: `sicky_broker_publish/handler/subscribe_total` + durations, labelled `{broker,topic,result}` (`ok/error/panic/dup/acked/nacked/requeued`); `sicky_broker_connected{broker}` gauge on Connect/Disconnect.
  - **Job metrics**: `sicky_job_runs_total{job,task,result=ok/error/timeout/panic}` + duration, `ticks_total`, `registered_total`, `running` gauge. Non-timeout cron handlers are wrapped too (panic re-panics after recording).
  - **Runner metrics**: `submit/try_submit/task_runs_total{result}` (`enqueued/full/full_timeout/dropped_*`), `queue_depth`/`inflight`/`workers` gauges, task duration.
  - **Registry metrics**: `sicky_registry_ops_total{backend,op,result}` + duration for register/deregister/load/watch/check (check has no histogram, result `ok/missing/error`), `instances` gauge on Load, `watch_events_total`.
  - **Infra metrics**: `sicky_infra_ops_total{infra,op,result}` + duration + `sicky_infra_up{infra}` + `init_total`. Redis (hook), Bun (QueryHook) and Mongo (CommandMonitor) observe every operation automatically; Elastic/S3 record `ping`/`head_bucket` probes; all 10 `Init*` count init outcomes (nil cfg = disabled, untouched) and `Clear*` drops `up` to 0.
- **Cardinality rules**: `topic` labels stay full-fidelity by decision — watch `/metrics` line count after adding high-cardinality topics. `method` is normalized through `metrics.NormalizeHTTPMethod` (standard methods only, everything else → `OTHER`) and an unmatched `route` collapses to `metrics.NormalizeRouteLabel`'s `unmatched` (fiber resolves the route only after the chain, see `routeLabel`); both are client input and would mint one series per request otherwise. Matched route templates stay verbatim. `uri/url/dsn` must NEVER enter labels (use `RedactDSN` for logs only).
- **Known metric bugs** (see TODOs): gRPC unary interceptors are assembled with a single `ChainUnaryInterceptor(tracing, logging)` / `WithChainUnaryInterceptor` call (merged — this was originally believed to overwrite, but repeated `Chain*` calls append rather than overwrite on grpc ≥ v1.83.2, so nothing was lost; a single call is version-proof and is what sicky now uses); streaming RPCs now have `ChainStreamInterceptor`/`WithChainStreamInterceptor` (tracing + logging + counters). The legacy `logger/tracer` Fiber middlewares were deleted in the v3 migration — `server/fiber`'s built-in chain owns `sicky_server_requests_total{server="fiber"}`.

### 3.7 Manager Conventions
- `NewManager(cfg, appName, appVersion)` is nil-config safe (calls `Ensure()`) and creates `prometheus.Registry`, capturing `cfgVar` for `/config` exposure.
- 8 handlers: `MetricsPath` (`/metrics`, public), `HealthPath` (`/health` with `collectComponentHealth` for 10 infra types + registered business checkers → `healthy/not_configured/unhealthy`; only `unhealthy` degrades overall status; infra probes concurrent + panic-safe, business checks via `runCheck` with their own deadline), `LivePath` (`/live`, static 200), `ReadyPath` (`/ready`, same aggregation as `/health`), `VersionPath`, `InfoPath`, `ConfigPath` (403 if `ExposeConfig==false`, secrets redacted when exposed), `ServicePoolPath` (`registry.GetPool()` snapshot). `/config` + `/services` require `Authorization: Bearer <auth_token>` when `ManagerConfig.AuthToken` is set, else loopback-only. `http.Server` carries `Read/Write/IdleTimeout` (defaults 10/10/60s); default bind is `127.0.0.1:8888` (loopback) — an external bind must be configured explicitly.
- `Start()` does `wg.Add(1)` + `go func() { defer wg.Done(); srv.ListenAndServe() }`; `Stop()` does `Shutdown` with `ShutdownTimeout` then `wg.Wait()`. All Manager and server goroutines use `defer wg.Done()` (fixed in `server/http`, `server/tcp`, `server/udp`); `go func()` signatures carry no `error` return — errors are logged internally.

### 3.8 Code Format Details
Project-specific formatting rules beyond `gofmt`/`gofumpt` (apply to all `*.go` except `registry/mdns/` + `cli/template/`):
- **R1 block-then-code**: a compound block (`if`/`for`/`range`/`switch`/`select`) followed by more sibling code must be separated by a blank line. Consecutive compounds (`if` right after `}`) are exempt — only block-then-*code* needs it.
  ```go
  // good
  if err != nil {
      return err
  }

  metrics.ObserveInfraOp(...)
  ```
- **R2 return-blank**: a `return` preceded by sibling code needs a blank line above it, unless the line above ends with `}`/`{` or the `return` is the first statement of its block.
  ```go
  // good
  metrics.CountInfraInit("redis", err)

  return nil, err
  ```
- **Log lowercase**: structured logger messages (`*.Logger.(Info|Error|Warn|Debug|Trace|Fatal)(Context)?`) start lowercase; a leading all-caps acronym is lowercased whole (`"TCP server created"` → `"tcp server created"`, never `"tCP ..."`). Out of scope by decision: CLI user-facing `stderr` output, test assertions.
- **Spelling**: US English (`misspell` gate). Intentional exceptions keep a deprecation note instead of being "fixed" (e.g. `TickerHander = TickerHandler` at `sicky.go:87-88`).
- **Necessary comments**: exported symbols carry `// Name ...` docs ending with `.` (`revive` + `godot` gates); every non-trivial error branch / `Validate()` rejection / magic-number default states *why* in one line (e.g. `infra/redis.go` "Close the handle opened above instead of leaking its sockets", `runner/static/static.go:118-120`).

## 4. Key Packages & Directories
- `/broker`: Messaging abstraction (`broker/broker.go`) + NATS, JetStream, NSQ implementations.
- `/client`: Client abstraction + gRPC, HTTP, TCP, UDP, WebSocket implementations (top-level `client.Config` empty with `Ensure()`, sub-clients have `Ensure()` + `Validate()` where applicable). gRPC client (`client/grpc/grpc.go`): `tls_cert_pem`+`tls_key_pem` load a real `X509KeyPair` (TLS 1.2+, half-config fail-fast via `ErrIncompleteTLSConfig`, never silent plaintext); `Addr` mode dials directly, `Service` mode resolves via the registry pool (`resolveGRPCAddrs` from `Instance.Servers[type==grpc]`) with a `NotifyChan`-driven watcher goroutine (+30s resync, stopped on `Disconnect`).
- `/cli`: CLI scaffolding — `sicky serve/new/generate/version/help` (`cli/sicky.go:46 Run()`), transports stdio/http.
- `/cmd/sicky`: Entrypoint (`cmd/sicky/main.go`).
- `/infra`: Infrastructure drivers — 10 files at `infra/*.go` (Redis, Bun/SQL, Badger, Ristretto, Mongo, Clickhouse, MQTT, NATS, S3, Elasticsearch). No interface — each is a standalone module. No `infra/interface.go`.
- `/internal`: Internal helpers (`internal/context.go`, `internal/leakcheck` — the shared goroutine-leak policy every test package's `TestMain` uses).
- `/job`: Job abstraction + Cron (`job/cron`), Ticker implementations. Handlers are `func() error` / `func(time.Time, uint64) error` (no ctx — kept for compatibility); both `Task` types carry an optional `Timeout` watchdog (expiry reports failure; the leaked run cannot be killed).
- `/logger`: Built-in structured logger (`GeneralLogger` at `logger/general.go`), gRPC logger adapter (`logger/grpc.go`).
- `/metrics`: Prometheus counter definitions and registry helpers (`metrics/metrics.go`).
- `/registry`: Registry abstraction + Consul, Redis, Local (file-based JSON at `registry/local/local.go`) implementations. Local requires an absolute `registry_file_path` (`Validate`, fail-fast nil), `MkdirAll` is `0700` everywhere, and `CleanupOnStart` only removes `<uuid>.json` files. `registry/mdns/` is **deprecated** (100% commented out, kept deliberately). `registry/pool.go` exposes `NotifyChan()` (stable across `PurgePool`, nil before `InitPool`) for live discovery subscribers such as the gRPC client watcher.

## 6. AI Agent Instructions
When working on this codebase:
1.  **Respect Interfaces**: Use the abstractions defined in `broker`, `server`, `registry`, etc., rather than implementation-specific types, except in the orchestrator (`sicky.go`) where concrete type access is necessary for implementation-specific methods (e.g., `Watch()`, `GracefulStop()`).
2.  **Surgical Edits**: Use targeted replacements to maintain the existing coding style and license headers.
3.  **Ensure Defaults**: When adding new configurations, always implement the `Ensure()` method on both `Options` and `Config` structs to provide defaults. All top-level empty `Config` structs already have nil-safe `Ensure()` — keep them in sync when touching those packages. Infra adds `Validate()` next to `Ensure()`: presence-means-enabled abort on missing required fields; timing fields use zero-fills-default / negative-aborts.
4.  **Nil-Guard Globals**: When adding infra init functions, wrap the global variable assignment with `if Xxx == nil { Xxx = client }` (`infra/*.go:56-76`).
5.  **Wire Metrics**: When adding new server or client protocols, add a Prometheus counter in `metrics/metrics.go` and wire its `.Inc()` call at the appropriate insertion point (server: interceptor/middleware before handler or before `OnData` loop; client: first statement of `Call()`/`Invoke`). When adding infra/broker/job/runner/registry operations, use the matching `Observe*` helper (`ObserveInfraOp`, `ObserveBrokerPublish/Handler`, `ObserveJobRun`, `ObserveRegistryOp`) so counter+histogram stay paired. `server/fiber`'s built-in chain owns the `server="fiber"` series — never add a second counting middleware on the same app.
6.  **Follow the Manager**: Health checks and metrics should be exposed via the Manager HTTP server (`manager.go`) — do not start separate metric servers.
7.  **No `context.TODO()`**: Use `context.Background()` for static initialization, or propagate a proper context for operations that need cancellation or deadlines. The codebase has 0 `TODO` contexts.
8.  **Goroutine Cleanup**: All server/manager goroutines must use `defer wg.Done()` to prevent `wg.Wait()` from hanging in `Stop()`. Drop the `error` return type from `go func()` signatures — errors should be logged internally.
9.  **gRPC Interceptors**: Merge tracing + logging into a single `grpc.ChainUnaryInterceptor(tracing, logging)` / `grpc.WithChainUnaryInterceptor` call; do not call `ChainUnaryInterceptor` twice. Streaming RPCs must have `ChainStreamInterceptor`/`WithChainStreamInterceptor` (tracing + logging + counters).
10. **Config Validation**: Extend `validateConfig()` (`sicky.go`) when adding timing/size fields — Viper env zeroing is silent for `int` fields.
11. **CORS Deny-by-Default**: Both HTTP stacks whitelist origins (`server/http/cors.go`, `server/fiber` via `CORSConfig`); empty `AllowedOrigins` emits no ACAO headers. `*` + `AllowCredentials` is illegal — `Validate()` rejects it, both server constructors fail closed (error log + deny-all), and `NewCORSMiddleware` drops the wildcard. Never reflect an arbitrary `Origin` with credentials; the deprecated `server/http.CORSMiddleware` is now a deny-all alias — use `NewCORSMiddleware` with an explicit whitelist.
12. **Hot-loop backoff/logging**: TCP accept and UDP read loops use `utils.NewBackoff` (capped exp + jitter) + `utils.NewLogSampler` (default 5/s, cap-rejects 1/s, `suppressed` count attached) — never fixed-sleep + per-error logs. UDP computes `addrKey` once per packet and shares it between limiter and session lookup.
13. **Code Format Details**: apply §3.8 on every edit — blank line after block-then-code (R1) and above `return` (R2), lowercase log messages, US spelling, why-comments on error branches. `gofmt`/`gofumpt` do NOT enforce R1/R2 — self-check the diff before finishing.

### 6.1 Local Verification Gate
There is **no CI** in this repository. The gate is enforced locally by a `pre-commit` hook. Enable it once per clone:

```sh
make hook-install    # sets git config core.hooksPath .githooks (local config, not versioned)
```

Then:

```sh
make verify          # the per-commit gate: fmt-check, vet, lint, build, race (~19s warm)
make full            # additionally tidy-check, vuln, cover — run before releasing
```

`make verify` is what the hook runs, so a commit cannot land without it. Bypass with `git commit --no-verify` only when a failure is provably unrelated to the staged change. `make help` lists every target.

Two deliberate deviations from the recipe this section used to spell out inline:

- `fmt-check` runs `golangci-lint fmt --diff`, **not** `gofmt -l .`. The `formatters` section of `.golangci.yml` enables `gofumpt` and `goimports` (with `local-prefixes: github.com/go-sicky/sicky`) on top of `gofmt`, so `gofmt -l` under-checks. Import grouping is machine-enforced by `golangci-lint fmt`, not maintained by hand.
- `tidy-check` runs `go mod tidy -diff`, which reports without writing. The old `go mod tidy && git diff --exit-code` recipe mutates the tree first and leaves it dirty on failure.

**`golangci-lint` is the authoritative linter**, and the only thing that enforces §3.8. `gofmt`/`go vet`/`go test` do not catch R1/R2 or lowercase-log violations.

**Optional scanners** (not part of `verify`, but run them when touching dependencies or security-sensitive code):
- `make vuln` — reachability-aware dependency CVE scan. Two known entries are expected and are listed in `.vuln-allow` with their reasoning: `GO-2026-5932` (`golang.org/x/crypto/openpgp`, unmaintained, no fix, reachable only through viper's blank `_ "github.com/spf13/viper/remote"` import — not exploitable by sicky) and `GO-2026-6443` (grpc server panic on a missing `:authority`; the unguarded `handler_server.go` path is reachable only via `grpc.Server.ServeHTTP`, which sicky never calls — it uses `Serve(lis)`, whose authority guards already exist at v1.84.0, and v1.84.0 is the newest stable release, so the only "fix" is a `-dev` pseudo-version that must not be pinned into a released framework). Re-check both when grpc ships v1.85.0 stable. `govulncheck` has no allowlist flag, so `scripts/vuln-allow.sh` diffs its findings against `.vuln-allow`; a **new** advisory fails the script.
- `gosec -quiet -fmt=text ./...` — **do not treat its output as a gate.** The standalone binary does not read `.golangci.yml` and its suppression token is `#nosec`, not `//nolint:`, so it re-reports findings that `golangci-lint` already suppresses (in-source `//nolint:gosec` annotations and the `cli/.*\.go` exclusion rule). Where the two disagree, `.golangci.yml` wins.

**Regression-test discipline**: every fix ships with a test, and every test ships with a **negative control** — revert the source, confirm the test fails for the *right* reason, then restore. A control that passes means the assertion is not exercising the code path. After restoring a backup, verify the content with a `grep`; never trust the copy's exit code. A control that fails to *compile* is not a control either — it proves nothing about the assertion.

**Goroutine leaks**: any package whose own source starts a goroutine carries a `TestMain` calling `goleak.VerifyTestMain(m, leakcheck.Options()...)`. Adding a goroutine to a package without one is a gap; a new exemption belongs in `internal/leakcheck`, not in a `TestMain`, and must name why the goroutine has no stop. Two caveats the checks have already caught, both worth remembering: `goleak` reports only on an otherwise-successful run, so a package that already fails elsewhere tells you nothing about leaks; and `runCheck` deliberately abandons an overrunning health checker, so a test that starts one must not overshoot the deadline by more than it can afford.

**Test hygiene that the leak check depends on**: never let a test share `http.DefaultTransport`'s process-global idle pool (give it a dedicated `Transport`, `DisableKeepAlives`, and `CloseIdleConnections`), and never hold a busy loop without throttle while something else needs the scheduler — an unthrottled poller under `-race` starves the code it is meant to race.

- `service.Ordered()` added; `service.Services()` still returns the unordered map.
- `logger.GeneralLogger` gained the `Enabled` method — an out-of-tree implementer of the interface must add it.
- **`NewGeneral` no longer calls `slog.SetDefault`.** This is the one breaking change: external code relying on the side effect will no longer have its `slog.Info(...)` routed into the sicky logger. In-repo impact is zero (`NewGeneral` is called once, at package init, and every in-tree call goes through `logger.Logger`). Callers that want the process default moved must call `slog.SetDefault` themselves.
- Six config keys that no code read are **deleted**: `standard.Config.DisableTrace` (it sat next to `DisableTracing`, so `disable_trace: true` silently left tracing ON), `service.Config.EnableManager`, all three `DisableWrappers` (standard/mcp/interactive), and `mcp.Config.Transport`/`Listen` (the transport is a construction argument, not configuration). `cli/template/project/mcp/config.json.gotmpl` lost its inert `"service": {"transport": "stdio"}` block.
- `service/interactive` is restartable (the `sync.Once` pair could never be reset); `Stop` before `Start` still marks the service stopped, because `interact()` reads a closed `done` as that marker.
- `metrics.NormalizeRedisCommand` bounds the Redis `op` label (go-redis derives `cmd.Name()` from the **first argument**, so `Do`/`NewCmd` callers previously minted one permanent series per distinct value). Typed go-redis methods keep byte-identical labels.

**Known residual risks (accepted, not defects)**: the grpc `GO-2026-6443` and x/crypto `GO-2026-5932` entries from §6.1; `client/websocket` (and the tcp/udp clients) have no real transport yet, so their `Connect`/`Disconnect` are no-op stubs returning nil; no CI (the §6.1 gate is manual).

### Fixed in the 2026-10-03 audit pass (P0 gate, P1 contracts, P2 concurrency)

**Test infrastructure added first, because without it nothing below had a regression net.** `go.uber.org/goleak` now backs a `TestMain` in every package whose own source starts a goroutine (root, cli, client/grpc, job/{cron,ticker}, registry/{consul,local,redis}, runner/static, server/{fiber,grpc,http,tcp,udp,websocket}, service/mcp/protocol, utils) — the list comes from grepping each package's own directory, excluding comment lines and the deprecated `registry/mdns`. `internal/leakcheck.Options()` holds the policy so the two unavoidable fasthttp exemptions (workerPool, `updateServerDate` — neither has a public stop) are justified once rather than in a dozen TestMains. `t.Parallel()` was deliberately **not** added: most packages share the global registries, the global Prometheus registry and the logger, so blanket parallelism would trade a real defect for flaky ones.

**P0 — local gate** (no CI by decision): `make verify` (fmt-check, vet, lint, build, race) via `.githooks/pre-commit`, `make full` adds tidy-check/vuln/cover, `make hook-install` sets `core.hooksPath`. `fmt-check` runs `golangci-lint fmt --diff`, not `gofmt -l`, because the `formatters` section enables `gofumpt`+`goimports` on top of `gofmt`. `vuln` is excluded from `verify` because it needs the network and a commit must not fail for an unrelated reason.

**P1 — contracts**: `utils.RedactDSN` is the single implementation (`tracer`/`infra` delegate) and its query-parameter leak list was extended; Manager `validatePaths` requires exact-match paths (no trailing `/`, no `{...}`) so a subtree pattern cannot shadow the bearer guard; the bearer throttle now runs **after** the token compare (a constant-time compare makes 429 and 401 cost an attacker identically, so gating before it bought DoS, not brute-force resistance) and is bucketed per source IP with a bounded table; all five `client.Call()` implementations return `client.ErrClientNotImplemented` instead of a silent no-op that still counted as a success; `metrics.NormalizeClientHost` collapses every non-empty outbound host to `other` (empty → `unknown`) at both `ObserveClientRequest` and `ClientErrorsTotal`, with a digest-keyed `pairCache` capped at 4096 overflow labels routed to a visible `sicky_metric_label_sets_dropped_total`; the five independent `ErrIncompleteTLSConfig` values are now one `server.ErrIncompleteTLSConfig` with per-implementation aliases (three of them carried a byte-identical message, which is why the duplication hid); `utils.CryptoPassword` is renamed `SHA256Digest` and documented NOT-for-passwords, with `CryptoPassword` kept as a deprecated delegating alias; the three `main.go.gotmpl` scaffolds check `Init`/`ConfigUnmarshal`/`Run` and exit non-zero on failure (`ErrVersionShown` returns cleanly) instead of exiting 0 having served nothing.

**P2 — concurrency** (each verified by reproduction first; two claims were retracted):
- `MustInfra`/`MustBroker`/`MustRegistry` are exported, and `Run` mutated them without a lock — ten in-place writes spread across startup. A concurrent read is `fatal error: concurrent map read and map write`, an unrecoverable process kill. `Run` now keeps its bookkeeping in a private copy and republishes the whole set under `mustMu` at defined instants; `MustInfraSnapshot`/`MustBrokerRequired`/`MustRegistryRequired` are the supported read path. Direct reads of the exported vars remain unsynchronized by necessity and say so.
- `server/websocket` had no `stopping` flag while all five sibling servers did, so a `Start` landing inside an in-flight `Stop` drain added goroutines to the very `WaitGroup` that drain was waiting on — extending it by work it had just created. `Start` now refuses; `stopping` is cleared only after the drain.
- `utils.IsClosedConnError` (extracted from `server/fiber`) is now also applied by `server/websocket`, whose structure is identical. Restarts were failing ~15 runs in 40 with `use of closed network connection` — reported as a failed shutdown for a socket that was down. Now 0 in 40.
- `/health` + `/ready` propagate the singleflight leader's request context, so one scraper hanging up (an ordinary Prometheus timeout-and-cancel) failed the fan-out for every other scraper still connected, all rendering "unhealthy" for healthy backends. The probe now runs under `context.WithoutCancel`; the existing comment claiming this was safe was wrong.

**Retracted after measurement**: `websocket` restarting into a permanently-blocked session cap (the cap is enforced after the 101, which `TestSessionCapRejectsUpgrades` already documents and pins, and a restart re-accepted normally); `Run()` holding `runMu` for the process lifetime (a second `Run` queues and then executes normally — that is the documented restart path).

**Left adjacent and unfixed, deliberately**: `service/mcp/protocol`'s `HTTPTransport.Stop` does `_ = srv.Shutdown(ctx)`, so a shutdown that times out returns nil while the server keeps serving. It needs its own decision — report the timeout, or escalate to `Close`.

### Fixed in the 2026-10-03 audit pass, P3 (configuration contract)

**All 32 sensitive environment overrides were dead in every generated application.** viper's `AutomaticEnv` only resolves keys it already knows, so `sensitiveEnvKeys` exists to bind them explicitly — but it bound the *flat* path (`manager.auth_token`), which is only correct for a caller that unmarshals a `sicky.Config` directly. Every scaffold nests it (`{"sicky": {"manager": {...}}}`), so the bound key had nowhere to land. `SICKY_MANAGER_AUTH_TOKEN`, `SICKY_TRACER_DSN`, `SICKY_INFRA_BUN_DSN` and the rest were accepted by the operator, reported by `ignoredEnv` as *known*, and never read. The list's own comment predicted exactly this outcome ("a silently weaker — or differently configured — process than intended") and then produced it. `ConfigUnmarshal` now derives the paths from the caller's own type (`configprefix.go`) and binds each key at every one of them, always to the same canonical variable name derived from the key *relative to* `Config`. The flat path is always included, so a direct `*Config` target and a target with no `Config` behave exactly as before. Note that `TestBindSensitiveEnvResolvesRegistryPassword` proved the mechanism on an anonymous struct with `registry` at the top level — the one shape no generated project has.

**Unknown configuration keys were silent.** viper drops a key it cannot map, so `infra.bu` or `manager.auth_tokn` starts a service with the setting quietly absent — no database, no auth token — and says nothing. `ConfigUnmarshal` now warns about any key under a framework-owned prefix that matches no field. Two deliberate limits: only keys the framework owns are checked (it cannot know what the application put under `server`/`service`, and a check that guesses is a check operators learn to ignore), and it warns rather than refuses to start (a typo on an unread key is a worse outcome than the typo). Keys are reported at the first segment that does not resolve, not at the leaf, because viper only knows leaves — `sicky.infra.bu` names the block the operator wrote, `sicky.infra.bu.dsn` names one they did not. `TestSensitiveEnvKeysAllNameRealFields` replaces the hand-written pair-key phantom check with a schema walk over all 32 entries.

**Every generated service shipped with no `/metrics` and no `/health`.** `ManagerConfig.Enabled` reads a nil block as disabled, because presence is the signal — a bare bool cannot express "the block is here, run it" and "there is no block, do not" at once. That contract is deliberate and stays. The scaffold violated it: no `config.json.gotmpl` carried a `manager` block. Verified on a project generated before this change — both endpoints refused the connection and the instance registered `manager_address:"" manager_port:0` into the registry, handing peers a discovery record pointing at nothing. All three templates now carry the block (loopback default, `expose_config: false`, no `enable` key), and `Run` warns when it is absent, naming what will not be served.

**Deferred, and it is a feature rather than a fix**: closing the config-contract split properly means giving `sicky.Config` a `Servers`/`Clients`/`Jobs` section and dropping the scaffold's `ConfigDef` wrapper, so the framework owns those keys too — which would also bring them under the env binding and the unknown-key check above. That is a design decision (typed fields vs a map, whether `Run` constructs them or only configures them) with a behavior change, not a repair, and it wants its own review.

### Fixed in the 2026-10-03 audit pass, follow-ups

**The scaffold's config keys are now pinned by a test.** `cli/scaffold_config_test.go` renders each real template, parses the result, and resolves every key against the struct meant to receive it — including `server` and `service`, which the runtime check deliberately skips. A separate test covers the manager block on its own (presence is a different failure from resolvability) and pins the three defaults that matter: loopback bind, `expose_config` false, no shipped credential. The `ConfigDef` is restated in the test rather than imported; the service field is a concrete pointer per project type because a field typed `any` has no structure to walk — the first version used `any` and passed for the wrong reason on the template that has no `service` block.

**`cli` builds its binary once.** Every scaffolding test rebuilt it: fourteen calls at ~7s put the package at 99s under `-race`, enough to make a full `make verify` fail intermittently on load. TestMain builds once — **99s to 7.4s**. The leak check moved into that TestMain by hand because `goleak.VerifyTestMain` calls `os.Exit` and would skip the temp-dir cleanup (it did, leaving a 148MB binary per run). The options are built before `m.Run` so `IgnoreCurrent` snapshots the goroutines from before the first test.

**`registry/consul` lost tag order on every read.** Tags were written as one Meta key per element and read back in map-iteration order, so the same service produced a different order on every `Load` — and `Load` runs on every pool purge tick, so it flapped rather than merely losing the order once. `local` and `redis` were unaffected because they marshal the whole `Instance`. Tags now travel as one JSON array; the per-index keys are still *read* (ordered by index) so a cluster registered by an older version does not lose them on upgrade, and they stop being written. The logic moved to `registry/consul/encode.go` as pure functions because it needed a concrete `*api.Client` to reach before, which is why the package sat at 2.8% coverage with none of it on this path; it is now 15.9%.

### Fixed in the 2026-10-04 audit pass (broker codec, logger)

**A failed `Message.Format` wiped the payload and mislabelled the codec.** `json.Marshal` and `msgpack.Marshal` were assigned straight into `m.Body`, and both return nil bytes alongside the error, so an encode failure left the message half-written: `Body` emptied, `Mime` changed to a codec that no longer described it. The harm is silent at both ends — the message publishes empty and the receiver's `Scan` decodes nothing while reporting success — and reusing a `Message` after a failed encode destroyed whatever it already carried. `Raw()` already guarded exactly this for its own path (it falls back to `m.Body` rather than sending an empty payload); `Format` had no equivalent. It now encodes into a local and commits `Body` and `Mime` only on success. The pre-existing `TestMessageFormatError` only asserted that an error came back and never looked at the state, which is why this survived the earlier `Mime` fix on the same function.

**One of the three new tests was wrong and had to be rewritten.** It asserted that `Scan` must not report success on the message a failed `Format` left behind — but `Scan` on a `MsgRaw` message is a documented passthrough returning nil, so the assertion demanded a property the API does not have. Replaced with the wire round trip, which is the observable form of the invariant.

**Retracted, with the reason recorded because it nearly shipped**: `broker/nats.Subscribe` was converted to the reserve-then-call pattern `jetstream` and `nsq` use, on the belief that nats makes a server round trip. The vendored `nats.go@v1.54.0` says otherwise — `subscribeLocked` only does `bw.appendString` plus an asynchronous `kickFlusher`, and core `Subscription.Unsubscribe` does not await a reply either (`deleteConsumer`, the actual round trip, is JetStream-only). So the write lock nats held was held across an in-memory append: no latency defect, and the change was reverted rather than published on a premise the source disproves. `jetstream` and `nsq` genuinely need the reservation — `CONSUMER.DURABLE.CREATE` waits for a reply — which is why the asymmetry between the three backends is correct rather than an oversight.

**The `ln` family embedded a newline inside the log message.** `Infoln`/`Warningln`/`Errorln`/`Fatalln` built their message with `fmt.Sprintln`. Those variants exist to reproduce the stdlib `log` spacing (operands separated by a space) and inherited stdlib's trailing newline too — but in stdlib that newline terminates a line, because the record is line-oriented. A slog handler already terminates the record, so the newline landed *inside* the message: a JSON record whose `msg` ends in `\n`, followed by the record's own terminator. A consumer splitting records on newlines still sees one record; every consumer reading `msg` gets a stray control character that breaks any comparison against the intended text. `spaced()` renders with `Sprintln` and trims exactly the one newline it appends, so a newline the caller put inside an operand survives. `Fatalln` ends the process and cannot be exercised through the logger, so `spaced` is asserted directly — that is what actually covers it.

**`logger.Level()` is a silent no-op on two of three construction paths — documented and pinned, deliberately not changed.** `NewGeneral` and `NewGRPC` allocate a `*slog.LevelVar` on every call, but it reaches a handler only where the constructor built that handler (`NewGeneral(nil)`). `NewGeneral()` adopts `slog.Default()` and `NewGeneral(l)` adopts `l`; both own their own threshold, and `Level()` writes a var nothing reads — no output change, no error. Measured rather than inferred: after `Level(ErrorLevel)` on the no-argument form, `Debug` still wrote its record. There is no safe behavior fix. Building the handler for the no-arg form would reroute an application's logs away from `slog.Default()` and destroy the reason that form exists; wrapping a supplied handler would either override the caller's threshold or make `Level` able to raise but not lower it, and either asymmetry is worse than the trap. So the constraint is stated on both interface methods and both constructors, and `logger/level_test.go` pins the whole matrix — including what to do if a future change widens it, which is when that test fails and says so. The same test pins the property that does hold everywhere: `Enabled` is truthful on all three forms, because the hot broker and runner paths guard their variadic `Debug`/`Trace` calls with it and a wrong `true` drops real logs. `GRPCLogger` has no `Enabled` at all, so on its unwired paths the threshold cannot be read back even indirectly.

**Docs synchronized**: AGENTS.md §3.4 gained the `Format` failure contract; both READMEs' NATS sample now checks the codec errors (the Chinese README already carried a note saying callers must, while the sample right above it ignored them — and the English one had neither); both READMEs' structured-logging bullet carries the `Level` construction caveat.

### Fixed in the 2026-10-04 audit pass (job metrics, tracer, infra config, registry pool)

Four lanes were audited in parallel — `job`+`runner`+`service` in-house, and `tracer`, `infra`, `registry` by independent read-only agents whose candidates were each re-verified here before anything shipped. Six defects fixed, one deferred, four retracted.

**`sicky_job_runs_total` classified run outcomes by reading the error text.** Both backends did `strings.Contains(err.Error(), "timed out")` / `"panicked"`, so the watchdog verdict was distinguished from a handler failure by *wording*. `errors.New("upstream request timed out after 30s")` is an entirely ordinary handler error — the downstream service being slow is the handler's problem — and it was counted as a watchdog timeout, in the one metric an operator consults to decide whether their jobs are too slow. `job.ErrTaskTimeout` / `job.ErrTaskPanic` are now wrapped by the watchdog and `job.Classify(err)` keys off identity via `errors.Is`, so a caller can also tell the two apart without reading text. The result labels are exported constants (`job.ResultOK/Error/Timeout/Panic`) and are pinned to the literal strings the dashboard already uses. Both backends had to alias their `job` import (`jobpkg`) because the receiver is also named `job`.

**The tracer was the only process-wide singleton that was stopped at shutdown but never cleared.** `sicky.Run` calls `broker.Clear()` and `registry.Clear()` for exactly this reason — a second `Run` must not keep pointing at a disconnected instance — but only `tracer.Default().Stop()`, and `tracer.Clear()` had **zero callers** anywhere in the repo. Since `tracer.Set` is first-wins, the stopped tracer stayed the process default forever and a second `Run` could never promote its replacement: every server and client resolved a provider that had already been shut down, so nothing was exported, silently. Extracted `stopTracer()`, which clears unconditionally — a tracer that failed to stop is no better a default than one that did, and no path can revive a shut-down provider.

**A malformed Uptrace DSN printed the token in clear to stderr.** `uptrace-go` builds every DSN rejection with the raw input embedded (`dsn.go`: `fmt.Errorf("DSN=%q does not have a host", dsnStr)`) and prints it through a package logger wired to `os.Stderr` at init. The token *is* the DSN's userinfo, so a typo in the host or the scheme — an ordinary operator mistake — leaked the credential to fd 2, outside sicky's logger and past every redaction this package does on its own lines (six `tracer.RedactDSN` call sites). `uptrace.SetLogger` is now taken over before the DSN is handed over, routing the dependency's diagnostics into sicky's logger through `redactUserinfo`, which strips just the userinfo and keeps the reason ("does not have a host"). `utils.RedactDSN` was the wrong tool: on anything that looks like a secret it returns the single word `REDACTED`, discarding the part the operator needs. The bare `token@host` form is matched too — that is precisely what "does not have a scheme" reports — which means an email address in a diagnostic is also redacted. Deliberate: over-redacting an address costs nothing, leaking a token costs a credential.

**`Propagator()` rebuilt the composite propagator on every call.** The propagator is immutable after construction, and `Propagator()` is reached once per inbound request (`Extract`) and once per outbound span (`Inject`) from five server and client sites. Measured at 43 ns / 89 B / 4 allocs per call; now `sync.OnceValue`, at **2.4 ns / 0 allocs**.

**`InitPool()` reset `Services` without the pool's own mutex.** Every other writer (`PurgePool`) and every reader (`GetPool`, and the exported `Pool` methods, which take only `p.RWMutex`) guards `Services` with it, so the two-lock discipline was load-bearing in one direction and violated in the other. Reachable because `InitPool` is exported and hands out the live pool: a caller using the returned pool races a second `Run`'s `InitPool`, and `runMu` serializes `Run` bodies without excluding pool readers. Confirmed by the race detector; the fix is `currentPool.Lock()` around the swap.

**`Pool.RegisterService` stored the caller's `*Service` by reference.** It was the only pool write with no `cloneService` — `RegisterInstance`, `GetService`, `GetInstance`, `GetInstances` and `PurgePool` all deep-copy, and the file documents that at each site, with `TestPurgePoolCopiesInstances` existing to pin it. A caller reusing its `Service` (or the `Instance` values inside it) mutated what every reader saw, concurrently with readers holding `p.RLock()`.

**`registry/local` disagreed with the other two backends about a benign event.** `Deregister` of an absent instance returned a hard error; consul's agent answers 200 for an unknown service id and redis's `HDel` returns `0, nil`. `sicky.Run` joins a `Deregister` error into its return, and the register-failure path calls `Deregister` precisely for an instance that may never have been written — so a double shutdown turned a clean shutdown into a failed one. And `Watch()` after `Stop()` returned `nil`, logged "local registry watcher started" and counted an `ok`, while its goroutine exited on the first select: `Stop` cancels `rg.ctx` permanently and it is never re-derived. Now `ErrWatchStopped`.

**`BunConfig.SlowDuration` was read by `Init*` but never reached `Validate()`.** The only `int` on the struct exempt from the negative-abort convention, so `"slow_duration": -1` silently disabled the query hook — indistinguishable from omitting the key. Now `ErrBunSlowInvalid`. Its doc comment also claimed "in milliseconds" and then admitted the value is never compared against a query's latency; the comment now says what it is.

**Deferred, and it is a design decision rather than a repair**: `registry/consul` `Register`→`Load` drops six of the thirteen `Instance` fields (`Type`, `AdvertiseAddress`, `Weight`, `Status`, `CheckEntryPoint`, `TTL`) — it is the only backend that does not JSON-marshal the whole `Instance`. `AdvertiseAddress` has a live consumer: `client/grpc`'s resolver falls back to `Instance.AdvertiseAddress`, so a peer relying on that fallback resolves to **no addresses** under consul while resolving fine under redis/local. Reproduced against a fake agent. Fixing it means choosing an encoding (Meta keys alongside the existing `meta-`/`topic-` prefixes) with a version marker and backward compatibility — a wire-format change, so it wants its own review rather than a drive-by.

**Retracted, each verified against the dependency source before shipping**:
- `infra/redis` sets `rdb.Options().TLSConfig` *after* `NewClient`, which looked like a silently-ignored TLS flag. It is not: `Client.Options()` returns `c.opt`, the same pointer the pools hold, and the dialer reads `opt.TLSConfig` lazily at dial time (`options.go:623-626`). The only stale value is `MaintNotificationsConfig.EndpointType`, auto-detected at construction from `TLSConfig != nil` — a maintenance-notification classification, unrelated to connection security. No defect.
- `infra`'s `ClickHouse`/`Clickhouse` and `NATS`/`Nats` alias pairs looked like a stale-global lead (each `Init*` appeared to write one while `Clear*` nils both). Both aliases are written inside the `mu` critical section; the false lead came from reading a truncated grep.
- `tracer`'s `ClampSampleRate` guard is genuinely unreachable (`Ensure` already guarantees `(0,1]`, so the clamp's domain is disjoint) — left as-is, it is harmless defence-in-depth, and the dead `Warn` is the only real cost.
- Composite `Extract` lets B3 override W3C `traceparent` (the last valid propagator wins). Self-consistent, since `Inject` emits both with the same IDs, and the sampling half is already closed by `WithRemoteParentSampled`. Changing precedence would alter trace linkage; left alone.

**Four mistakes of my own this round, all caught before commit** — recorded because each was a test that would have shipped a false signal:
- An inverted assertion in `tracer_shutdown_test.go` (`if !recording(...)` where the fatal belonged on `recording`) initially reported the fix as broken. Verified against a standalone probe before "fixing" anything.
- `${1}` instead of `${2}` in the redaction replacement template, which kept the token and dropped the host — caught because the test used the real `uptrace-go` message shapes rather than invented ones.
- The first redaction pattern required a `scheme://` prefix and so missed the scheme-less DSN, which is the single most common operator typo and the exact case that leaked in the first place.
- `goleak` failed the root package because my own test created a second tracer and never stopped it, leaking its batch span processor goroutine.
